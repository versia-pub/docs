Versia defines an API for server-to-server communication, mainly fetching and sending entities. It is namespaced and versioned, to avoid confusion with implementations' existing HTTP APIs.

## Well-known

<Endpoint
    name="Well-known"
    method="GET"
    path="/.well-known/versia"
    signature="exempt"
    accept="application/json"
>
    <div slot="response">
        A small JSON object with a single attribute:

        - `versions`: Supported Versia Protocol versions.
              - Versions marked as "Working Draft X" are represented as `0.X.Y`.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.well-known/versia HTTP/1.1
    Host: b.example
    Accept: application/json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/json

    {
        "versions": [
            "0.7.0",
            "0.6.0"
        ]
    }
    ```
    </Example>
</Endpoint>

## Entity Data

<Endpoint name="EntityData" method="GET" path="/.versia/v0.7/entities/{entity_type}/{id}">
    <div slot="parameters">
        - `{entity_type}`: The type of the entity to fetch, [not percent-encoded](/federation/http#encoding).
        - `{id}`: The ID of the entity to fetch.

        Example: `GET /.versia/v0.7/entities/pub.versia:groups/Group/1234` fetches the [Group](/extensions/groups) entity with ID `1234`.
    </div>
    <div slot="response">
        Entity data as JSON, as defined in its [Entity](/entities) definition document.

        `404` if there is no such entity, or if the requesting instance [may not fetch it](/federation#access). A deleted entity answers [`410` or `404`](/entities/delete#fetching-deleted-entities).
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.7/entities/User/1234 HTTP/1.1
    Host: b.example
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json

    {
        "type": "User",
        "id": "1234",
        // ...
    }
    ```
    </Example>
</Endpoint>

## Entity Collections

<Endpoint name="EntityCollection" method="GET" path="/.versia/v0.7/entities/{entity_type}/{id}/collections/{collection_type}">
    <div slot="parameters">
        - `{entity_type}`: The type of the entity to fetch, [not percent-encoded](/federation/http#encoding).
        - `{id}`: The ID of the entity to fetch.
        - `{collection_type}`: The type of the collection to fetch, [not percent-encoded](/federation/http#encoding).

        Example: `GET /.versia/v0.7/entities/User/1234/collections/followers` fetches the followers of the user with ID `1234`.
    </div>
    <div slot="response">
        **MUST** be either a [Collection](/structures/collection) or a [ReferenceCollection](/structures/collection#reference-collection) as JSON.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.7/entities/User/1234/collections/followers HTTP/1.1
    Host: b.example
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json

    {
        "total": 2,
        "items": [
            "a.example:f8b0d4b4-d354-4798-bbc5-c2ba8acabfe3",
            "c.example:2B27E62snga763"
        ]
    }
    ```
    </Example>
</Endpoint>

### Pagination

Collections **MUST** support pagination, using the following URI parameters:

- `offset`: The number of items to skip before returning the first item. Defaults to `0`.
- `limit`: The maximum number of items to return, from `1` to `40`. Defaults to `40`. Any other whole number **MUST** be clamped to that range.

A value that is not a whole number, or a negative `offset`, **MUST** be rejected with a `422 Unprocessable Entity` status code. An `offset` past the end returns empty `items` and the true `total`.

Items **MUST** be in a stable order, oldest first, so that new items do not shift earlier pages. Removing an item can still shift later ones, so a request walking through a collection may see an item twice or miss one.

A collection lists only the items the requesting instance [may fetch](/federation#access).

```http title="Example paginated collection request"
GET /.versia/v0.7/entities/User/1234/collections/followers?offset=10&limit=20 HTTP/1.1
Host: b.example
Accept: application/vnd.versia+json
```

## Instance Collections

[Instance Metadata](/entities/instance-metadata) has no ID, so its collections have their own path. They paginate like any other [collection](#pagination).

<Endpoint name="InstanceCollection" method="GET" path="/.versia/v0.7/instance/collections/{collection_type}">
    <div slot="parameters">
        - `{collection_type}`: The type of the collection to fetch: `moderators` or `admins`.

        Example: `GET /.versia/v0.7/instance/collections/admins` fetches the administrators of the instance.
    </div>
    <div slot="response">
        **MUST** be either a [Collection](/structures/collection) or a [ReferenceCollection](/structures/collection#reference-collection) as JSON.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.7/instance/collections/admins HTTP/1.1
    Host: b.example
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json

    {
        "total": 2,
        "items": [
            // ...
        ]
    }
    ```
    </Example>
</Endpoint>

## Inbox

The inbox receives entities from other instances, for every user on the instance (also known as a shared inbox). See [Inboxes](/federation#inboxes) for how delivery works.

<Endpoint name="Inbox" method="POST" path="/.versia/v0.7/inbox">

    Host: b.example

</Endpoint>
