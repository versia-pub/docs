The Social extension lets [Users](/entities/user) post [Notes](#note): text, images and other media, which other users can reply to and quote. It also gives each user a [collection of their notes](#notes-collection) and a list of featured notes.

Other extensions build on it, such as [Likes](/extensions/likes), [Share](/extensions/share), [Reactions](/extensions/reactions), [Polls](/extensions/polls), [Groups](/extensions/groups) and [Interaction Controls](/extensions/interaction-controls).

<Note>
    Notes are not just limited to microblogging. They can be used for any kind of content, such as forum posts, blog posts, image posts, video posts, audio posts, and even messaging.
</Note>

## Definition

### Note

A `Note` is a piece of content posted by a User.

        - `quotes`: [Reference Collection](/structures/collection#reference-collection) of [Note](#note) entities that quote this note.
    </div>

    <Field name="type" type="string" required>
        **MUST** be `pub.versia:social/Note`.
    </Field>
    <Field name="attachments" type="Media[]" required>
        Media attachments to the note. Any media type is allowed. The `content` can [place attachments inside the text](/structures/rich-text#media).
    </Field>
    <Field name="author" type="Reference" required>
        [Reference](/entities#reference) to the `User` considered the author of the note.
    </Field>
    <Field name="category" type="Category">
        Category of the note. Useful for clients to render notes differently depending on their intended purpose.

        <Values values={{
            microblog: "Short posts, like Twitter or Mastodon",
            forum: "Threaded discussions, like Reddit",
            blog: "Long articles, like WordPress or Medium",
            image: "Image posts, like Instagram",
            video: "Video posts, like YouTube or PeerTube",
            audio: "Audio posts, like SoundCloud or Spotify",
            messaging: "Chat messages, like Discord, Element or Signal",
        }} />

        A receiver **MUST** treat an unknown value as if `category` were left out.
    </Field>
    <Field name="content" type="RichText">
        The content of the note. It can [place the note's attachments inside its text](/structures/rich-text#media) with `img`, `video` and `audio`. Every user named in a [mention](/structures/rich-text#mentions) in it **MUST** also be listed in `mentions`.
    </Field>
    <Field name="device" type="Device">
        Device used to post the note. Useful for showing which app posted the note.

        <Field name="name" type="string" required />
        <Field name="version" type="string" />
        <Field name="url" type="string" />
    </Field>
    <Field name="visibility" type={'"public" | "subscribers" | "mentions"'} required>
        Who can see the note, besides its author:

        - `public`: Anyone.
        - `subscribers`: The author's subscribers, the users mentioned in the note, and the authors of the Notes it replies to.
        - `mentions`: Only the users mentioned in the note, and the authors of the Notes it replies to.
    </Field>
    <Field name="is_sensitive" type="boolean" required>
        Whether the note contains "sensitive content". This can be used with `subject` as a "content warning" feature.
    </Field>
    <Field name="mentions" type="Reference[]" required>
        [References](/entities#reference) to [Users](/entities/user) mentioned by the note. The content can also contain mentions, however only the mentions in this field **SHOULD** trigger notifications.
    </Field>
    <Field name="previews" type="LinkPreview[]" required>
        Previews for any links in the publication. This is to avoid the [stampeding mastodon problem](https://github.com/mastodon/mastodon/issues/23662) where a link preview is fetched by every instance that sees the publication, creating an accidental DDOS attack.

        Implementations **SHOULD NOT** trust previews, as a malicious remote instance could fake them to redirect users to malicious links.

        <Field name="link" type="string" required />
        <Field name="title" type="string" required />
        <Field name="description" type="string" />
        <Field name="image" type="string" />
        <Field name="icon" type="string" />
    </Field>
    <Field name="quoting" type="Reference">
        [Reference](/entities#reference) to the note that this note is quoting, if any. Quoting is similar to replying, but does not notify the author of the quoted note.
    </Field>
    <Field name="replies_to" type="Reference">
        [Reference](/entities#reference) to the note that this note is a reply to, if any.
    </Field>
    <Field name="subject" type="string">
        A subject for the note. Useful for clients to display a "content warning" or "spoiler" feature, such as on Mastodon. **MUST** be plain text, not [RichText](/structures/rich-text).
    </Field>
    <Field name="url" type="URI">
        Address of the note's page on its instance, for people to open in a browser. Software that shows the note elsewhere can link to it.
    </Field>

## Delivery and Access

A sender **MUST** [deliver](/federation#delivery) a Note to the instances hosting these users:

| Note | Delivered to |
| --- | --- |
| `visibility` is `public` | The author's subscribers, the users it mentions, and the authors of the Notes it replies to and quotes |
| `visibility` is `subscribers` | The author's subscribers, the users it mentions, and the authors of the Notes it replies to |
| `visibility` is `mentions` | The users it mentions and the authors of the Notes it replies to |

These instances [may fetch](/federation#access) a Note:

| Note | May be fetched by |
| --- | --- |
| `visibility` is `public` | Any instance |
| `visibility` is `subscribers` | Instances hosting a subscriber of the author, a mentioned user, or the author of a Note it replies to |
| `visibility` is `mentions` | Instances hosting a mentioned user or the author of a Note it replies to |

## Notes Collection

Every user has a `pub.versia:social/Notes` collection (at `/.versia/v0.7/entities/User/{id}/collections/pub.versia:social/Notes`). It is a [Collection](/structures/collection) of the Notes that the user has authored, and plays the role that an outbox plays in other protocols.

It **MUST** list only the Notes the requesting instance [may fetch](#delivery-and-access). For example, if Alice sends a Note whose `visibility` is `mentions` and that only mentions Bob, Alice's instance **MUST** return it in response to a request from Bob's instance, and **MUST NOT** list it in Alice's collection in response to a request from Joe's instance.

This collection is very useful for "backfilling" data when a new instance joins the network. By resolving the collections of all new users it encounters, a new instance can quickly catch up on all old notes.

## User Collections

The Social extension adds the following collections to the [User](/entities/user) entity:

- `pub.versia:social/Notes`: [Collection](/structures/collection) of notes authored by the user, described under [Notes Collection](#notes-collection).
- `pub.versia:social/Featured`: [Reference Collection](/structures/collection#reference-collection) of notes that the user wants to feature on their profile ("pinned" notes).

## Interaction Types

This extension registers the following [interaction types](/extensions/interaction-controls#interaction-types):
- `pub.versia:social/reply`, for sending a Note whose `replies_to` is the Note.
- `pub.versia:social/quote`, for sending a Note whose `quoting` is the Note.

## Versia Links

The Social extension adds the following [Versia Link](/links) actions:

- `notes/{instance}/{id}`: Open a note.
- `reply/{instance}/{id}`: Open the composer to reply to a note.
- `quote/{instance}/{id}`: Open the composer to quote a note.
- `compose/{text}`: Compose a new note. Text passed at the end will be added in the note compose field. Used for "Share with Versia" buttons on websites. It has no `{instance}`.

```text title="Viewing a note"
web+versia://notes/jim.example/0341e147rp002
```

```text title="Replying to a note"
web+versia://reply/bob.example/0341e147rp002
```
