Sometimes, users may want to move their data from one instance to another. This could be due to a change in administration, a desire to be closer to friends, or any other reason. Migration can be done using the migration extension.

## Behaviour

Migration happens in three steps:

### Prepare the New Account

- The user creates an account on the new instance, and puts the URI of the old account in the `previous` field of the new account.

### Request Migration

- The user requests migration from the old instance. The old instance checks that the `previous` field is set, and creates a migration entity.

- The migration entity is then distributed to every instance that interacts with the old instance, including the new instance.

- All instances that receive a verified migration entity (i.e. one where the `previous` field is correctly set on the new account) and support migration **must** then move all relationships (followers, followings, etc) from the old account to the new account in *their* internal database.

### Complete Migration

- The old instance sets the `new` field of the user to the URI of the new account, and marks it as "disabled" in its internal database.

## Entity Definition

<Entity name="Migration" type="pub.versia:migration/Migration" transient>
    <Field name="type" type="string" required>
        **Must** be `pub.versia:migration/Migration`.
    </Field>
    <Field name="author" type="Reference" required>
        [Reference](/types#reference) to the [User](/entities/user) who is migrating.
    </Field>
    <Field name="destination" type="Reference" required>
        [Reference](/types#reference) to the destination [User](/entities/user) on the new instance.
    </Field>

## User Extensions

The following extensions to [User](/entities/user) are used by the migration extension:

<Fields name="MigrationExtension" extension="pub.versia:migration" on="User">
    <Field name="previous" type="Reference" required>
        If this user has migrated from another instance, this property **MUST** be a [Reference](/types#reference) to the user on the previous instance.
    </Field>
    <Field name="new" type="Reference">
        If this user has migrated to another instance, this property **MUST** be a [Reference](/types#reference) to the URI of the user on the new instance.
    </Field>

    <Example slot="example" unchecked>
    ```jsonc title="Example"
    {
        // ...
        "type": "User",
        // ...
        "extensions": { // [!code focus:100]
            "pub.versia:migration": {
                "previous": "oldinstance.social:44df6e02-ef43-47e0-aff2-47041f3d09ed",
                // "new": "newinstance.social:73e999a0-53d0-40a3-a5cc-be0408004726",
            }
        }
    }
    ```
    </Example>
</Fields>
