The migration extension moves an account's subscribers and the users it is subscribed to to a new account. Notes and other entities stay where they are.

## Definition

### Migration

<Entity name="Migration" type="pub.versia:migration/Migration" transient>
    <Field name="type" type="string" required>
        **MUST** be `pub.versia:migration/Migration`.
    </Field>
    <Field name="author" type="Reference" required>
        [Reference](/entities#reference) to the [User](/entities/user) who is migrating.
    </Field>
    <Field name="destination" type="Reference" required>
        [Reference](/entities#reference) to the destination [User](/entities/user) on the new instance.
    </Field>

    <Inherits />

    </Example>
</Entity>

### User Extensions

The following extensions to [User](/entities/user) are used by the migration extension:

<Fields name="MigrationExtension" extension="pub.versia:migration" on="User">
    <Field name="previous" type="Reference">
        If this user is migrating or has migrated from another instance, this property **MUST** be a [Reference](/entities#reference) to the user on the previous instance.
    </Field>
    <Field name="destination" type="Reference">
        If this user has migrated to another instance, this property **MUST** be a [Reference](/entities#reference) to the user on the new instance.
    </Field>

    <Example slot="example" unchecked>
    ```jsonc title="Example"
    {
        // ...
        "type": "User",
        // ...
        "extensions": { // [!code focus:6]
            "pub.versia:migration": {
                "previous": "old.example:034syrr1jc002"
                // "destination": "new.example:0338qkp85w001"
            }
        }
    }
    ```
    </Example>
</Fields>

## Behavior

Migration happens in three steps:

### Prepare the New Account

The user creates an account on the new instance, and sets its `previous` field to a [Reference](/entities#reference) to the old account.

### Request Migration

The user requests migration from the old instance. The old instance checks that the new account's `previous` field names the old account, and sends a Migration entity.

It **MUST** [deliver](/federation#delivery) the Migration to the instances hosting a subscriber of the old account or a user it is subscribed to, and to the new account's instance. It **MAY** also deliver it to others.

A receiver **MUST** fetch the `destination` account, and **MUST** ignore the Migration if that account's `previous` field does not name the `author`.

Subscriptions then move through normal [Subscribes](/entities/subscribe):

- An instance hosting a subscriber of the old account **MUST** send a Subscribe to the new account for each of them, and drop their subscription to the old account.
- The new account's instance **SHOULD** accept these Subscribes automatically, even if the account has `manually_approves_subscribers` set.
- The new account's instance **MUST** send a Subscribe to each account in the old account's `subscriptions` collection. The target's usual rules apply, so one who manually approves subscribers still decides.

### Complete Migration

The old instance sets the `destination` field of the old account to a [Reference](/entities#reference) to the new account, and disables the old account.

It **SHOULD** keep serving the old account and its `subscribers` and `subscriptions` collections for at least 30 days, so that other instances can finish moving.

A [domain handle](/extensions/domain-handles#moving-instances) moves when the user changes its DNS record or file to name the new account.
