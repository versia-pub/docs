The Interaction Controls extension lets a user control who may interact with a Note, for example who may reply to it.

## Definition

The structure defined in this document **MUST** be inserted in the `pub.versia:interaction_controls` key of a [Note](/entities/note)'s extensions field.

<Fields name="InteractionControls" extension="pub.versia:interaction_controls" on="Note">
    <Field name="interaction_type">
        Not a literal key: each key is an [interaction type](#interaction-types), and its value says who may perform that interaction.

        <Field name="allowed" type="InteractionGroup[]" required />

        A user may perform the interaction if they are in any of the listed groups. The Note's author can always perform it. An interaction type that is left out allows everyone, and an empty list allows only the author.

        Values of `InteractionGroup`:
        - `everyone`: Includes every single User in the federation.
        - `mentioned`: Includes every mentioned User.
        - `followers`: Includes every follower of the author.
        - `following`: Includes every User that the author follows.
        - `mutuals`: Includes every mutual of the author (that is, every User that is both a follower and followed by the author).
        - `group`: Includes every User in the [Group](/extensions/groups) that this Note was posted to, if any. If Note is not posted to a [Group](/extensions/groups), this value has no effect.
    </Field>

    <Example slot="example" unchecked>
    ```jsonc title="Example"
    {
        "reply": {
            "allowed": [
                "group"
            ]
        },
        "pub.versia:likes/Like": {
            "allowed": []
        }
    }
    ```
    </Example>
</Fields>

## Behavior

The instance hosting the Note's author **MUST NOT** apply an interaction the user is not allowed to perform. Other instances **SHOULD** do the same when they have the data to check it.

A refused interaction **MUST** be [rejected](/validation#rejecting-entities). The instance **MAY** also tell the sender through the [Instance Messaging](/extensions/instance-messaging) extension.

Implementations **SHOULD** keep related [Collections](/structures/collection) and [Reference Collections](/structures/collection#reference-collection), such as a user's followers, up to date, so as not to refuse an interaction based on outdated data.

To avoid server load from constant Collection refreshing, implementations **MAY** only refetch associated Collections when forbidden interactions are detected, then recalculate permissions again.

## Interaction Types

The following interaction types apply to every Note:

- `reply`: Sending a Note with `replies_to` including this Note.
- `quote`: Sending a Note with `quoting` including this Note.

Extensions **MAY** register their own interaction types. The name of an interaction type is the `type` of the entity that performs it, such as `pub.versia:likes/Like` for the [Likes Extension](/extensions/likes).

## Example

```jsonc title="Example Usage"
{
    "id": "456df8ed-daf1-4062-abab-491071c7b8dd",
    "type": "Note",
    "visibility": "public",
    "created_at": "2024-04-09T01:38:51Z",
    "content": {
        "text/plain": {
            "content": "Hello, world :happy_face:!"
        }
    },
    // ...
    "extensions": { // [!code focus:7]
        "pub.versia:interaction_controls": {
            "reply": {
                "allowed": ["followers"]
            }
        }
    }
}
```
