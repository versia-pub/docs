The `ContentFormat` structure is used to represent content with metadata. It supports multiple content types for the same file, such as a PNG image and a WebP image.

## Definition

A `ContentFormat` structure is defined as follows:

```typescript
type ContentType = `${string}/${string}`;

type ContentFormat = {
    [key: ContentType]: {
        ...
    };
}
```

Each value in a `ContentFormat` is an object with the fields below. It **MUST** have exactly one of `content` or `url`.

<Fields name="ContentFormat">
    <Field name="content" type="string">
        The content itself, embedded in the entity as text. Binary formats **MUST** use `url` instead.
    </Field>
    <Field name="url" type="URI">
        Where to fetch the content from.
    </Field>
    <Field name="description" type="string">
        A human-readable description of the content. Also known as `alt` text.
    </Field>
    <Field name="size" type="number" numberType="integer">
        Size of the content in bytes. For inline `content`, this is the size of its UTF-8 encoding.
    </Field>
    <Field name="hash" type="string">
        SHA-256 hash of the content. **MUST** be encoded in lowercase hexadecimal. For inline `content`, this is the hash of its UTF-8 encoding.
    </Field>
    <Field name="thumbhash" type="string">
        Image in [ThumbHash](https://evanw.github.io/thumbhash/) format, encoded in base64 using the standard alphabet with padding, as defined in [RFC 4648, section 4](https://datatracker.ietf.org/doc/html/rfc4648#section-4).
    </Field>
    <Field name="width" type="number" numberType="integer">
        Width of the content in pixels. Only applicable to content types that have a width.
    </Field>
    <Field name="height" type="number" numberType="integer">
        Height of the content in pixels. Only applicable to content types that have a height.
    </Field>
    <Field name="fps" type="number" numberType="float">
        Frames per second, such as `29.97`. **MUST NOT** be negative. Only applicable to video content.
    </Field>
    <Field name="duration" type="number" numberType="float">
        Duration of the content in seconds. **MUST NOT** be negative. Only applicable to content types that have a duration.
    </Field>

    ```jsonc title="Images"
            "description": "A jolly horse running through mountains",
            "size": 453933,
            "hash": "91714fc336210d459d4f9d9233de663be2b87ffe923f1cfd76ece9d06f7c965d",
            "thumbhash": "3OcRJYB4d3h/iIeHeEh3eIhw+j2w",
            "width": 1920,
            "height": 1080
        }
    }
    ```

    ```jsonc title="Text Formats"
    {
        "text/plain": {
            "content": "The consequences of today are determined by the actions of the past. To change your future, alter your decisions today."
        },
        "text/markdown": {
            "content": "> The consequences of today are determined by the actions of the past.\n> To change your future, alter your decisions today."
        },
        "text/html": {
            "content": "<blockquote><p>The consequences of today are determined by the actions of the past.</p><p>To change your future, alter your decisions today.</p></blockquote>"
        }
    }
    ```

## Implementation Guidelines

### Representations

Each piece of data in the `ContentFormat` structure is meant to be a different representation of the same content. For example, a PNG image and its WebP version are different representations of the same image. Unrelated files or data **MUST NOT** be mixed in the same `ContentFormat` structure.

**Good:**
```json
{
    "image/png": {
        ...
    },
    "image/webp": {
        ...
    }
}
```

**Bad:**
```json
{
    "image/png": {
        ...
    },
    "application/json": {
        ...
    }
}
```

### Text

Text formats are ranked in this order:

1. `text/html`
2. `text/markdown`
3. `text/x.misskeymarkdown` (Misskey Flavoured Markdown, common on ActivityPub)
4. `text/plain`

Clients **SHOULD** use the first format on this list that they support.

Senders **SHOULD** include `text/html`, converting the content to HTML if it was written in another format. They **SHOULD** also include `text/plain`, for compatibility with other systems.

See [HTML](/validation#html) for sanitizing remote HTML.

### Images

Implementations **SHOULD** provide at least two versions of an image, if possible: one in the original format and another in a more efficient format like WebP/AVIF. This allows clients to choose the most suitable format based on their capabilities.
