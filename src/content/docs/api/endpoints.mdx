## Well-known

<Endpoint
    name="Well-known"
    method="GET"
    path="/.well-known/versia"
    signature="exempt"
    accept="application/json"
>
    <div slot="response">
        A small JSON object with a single attribute:

        - `versions`: Supported Versia Protocol versions.
              - Versions marked as "Working Draft X" are represented as `0.X.Y`.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.well-known/versia
    Host: b.social
    Accept: application/json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/json

    {
        "versions": [
            "0.6.1",
            "0.5.0"
        ]
    }
    ```
    </Example>
</Endpoint>

## Entity Data

<Endpoint name="EntityData" method="GET" path="/.versia/v0.6/entities/{entity_type}/{id}">
    <div slot="parameters">
        - `{entity_type}`: The type of the entity to fetch, URL-encoded.
        - `{id}`: The ID of the entity to fetch, URL-encoded.

        Example: `GET /.versia/v0.6/entities/pub.versia%3Agroups%2FGroup/1234` fetches the [Group](/extensions/groups) entity with ID `1234`.
    </div>
    <div slot="response">
        Entity data as JSON, as defined in its [Entity](/entities) definition document.

        `404` if there is no such entity, or if the requesting instance [may not fetch it](/federation#access). A deleted entity answers [`410` or `404`](/entities/delete#fetching-deleted-entities).
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.6/entities/User/1234
    Host: b.social
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json; charset=utf-8

    {
        "type": "User",
        "id": "1234",
        // ...
    }
    ```
    </Example>
</Endpoint>

## Entity Collections

<Endpoint name="EntityCollection" method="GET" path="/.versia/v0.6/entities/{entity_type}/{id}/collections/{collection_type}">
    <div slot="parameters">
        - `{entity_type}`: The type of the entity to fetch, URL-encoded.
        - `{id}`: The ID of the entity to fetch, URL-encoded.
        - `{collection_type}`: The type of the collection to fetch, URL-encoded.

        Example: `GET /.versia/v0.6/entities/User/1234/collections/followers` fetches the followers of the user with ID `1234`.
    </div>
    <div slot="response">
        **Must** be either a [Collection](/structures/collection) or a [ReferenceCollection](/structures/collection#reference-collection) as JSON.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.6/entities/User/1234/collections/followers
    Host: b.social
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json; charset=utf-8

    {
        "author": "b.social:1234",
        "total": 2,
        "items": [
            "a.social:f8b0d4b4-d354-4798-bbc5-c2ba8acabfe3",
            "c.social:2B27E62snga763"
        ]
    }
    ```
    </Example>
</Endpoint>

### Pagination

Collections **must** support pagination, using the following URI parameters:

- `offset`: The number of items to skip before returning the first item. Defaults to `0`.
- `limit`: The maximum number of items to return, from `1` to `40`. Defaults to `40`. Any other whole number **must** be clamped to that range.

A value that is not a whole number, or a negative `offset`, **must** be rejected with a `422 Unprocessable Entity` status code. An `offset` past the end returns empty `items` and the true `total`.

Items **must** be in a stable order, oldest first, so that new items do not shift earlier pages. Removing an item can still shift later ones, so a request walking through a collection may see an item twice or miss one.

A collection lists only the items the requesting instance [may fetch](/federation#access).

```http title="Example paginated collection request"
GET /.versia/v0.6/entities/User/1234/collections/followers?offset=10&limit=20
Host: b.social
Accept: application/vnd.versia+json
```

## Instance Collections

[Instance Metadata](/entities/instance-metadata) has no ID, so its collections have their own path. They paginate like any other [collection](#pagination).

<Endpoint name="InstanceCollection" method="GET" path="/.versia/v0.6/instance/collections/{collection_type}">
    <div slot="parameters">
        - `{collection_type}`: The type of the collection to fetch, URL-encoded: `moderators` or `admins`.

        Example: `GET /.versia/v0.6/instance/collections/admins` fetches the administrators of the instance.
    </div>
    <div slot="response">
        **Must** be either a [Collection](/structures/collection) or a [ReferenceCollection](/structures/collection#reference-collection) as JSON.
    </div>

    <Example slot="example">
    ```http title="Example request"
    GET /.versia/v0.6/instance/collections/admins
    Host: b.social
    Accept: application/vnd.versia+json
    ```

    ```http title="Example response"
    HTTP/1.1 200 OK
    Content-Type: application/vnd.versia+json; charset=utf-8

    {
        "total": 2,
        "items": [
            // ...
        ]
    }
    ```
    </Example>
</Endpoint>

## Inbox

The inbox endpoint is used for instances to send entities to each other. It is a single endpoint that can receive messages for every user (also known as a shared inbox).

The delivery mechanism is described further in the [Federation](/federation#inboxes) document.

<Endpoint name="Inbox" method="POST" path="/.versia/v0.6/inbox">
    <div slot="response">
        **Should** be `202 Accepted` with no body. See [Status Codes](/federation/http#status-codes) for all possible answers.
    </div>

    <Example slot="example">
    ```http title="Example request"
    POST /.versia/v0.6/inbox
    Host: b.social
    Accept: application/vnd.versia+json
    Content-Type: application/vnd.versia+json; charset=utf-8

    {
        "type": "Note",
        "id": "1234",
        ...
    }
    ```
    </Example>
</Endpoint>
