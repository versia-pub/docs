Sometimes, [Users](/entities/user) want to subscribe to each other to see each other's content. The `Follow` entity facilitates this, by defining a subscription relationship between two users.

- **Follower**: The user who is subscribing to another user. If `Joe` is following `Alice`, `Joe` is the follower.
- **Followee**: The user who is being subscribed to. If `Joe` is following `Alice`, `Alice` is the followee.
- **Subscribing**: Identical to **Following**. The act of subscribing to another user's content.

## Behaviour

Consider the following example:

`Joe`, a user on `social.joe.org`, wants to follow `Alice`, a user on `alice.dev`.

### Sending a Follow Request

To establish a follow relationship, `social.joe.org` **MUST** do the following:

1. Create a `Follow` entity with `Joe` as the author and `Alice` as the followee.
2. Send the `Follow` entity to `alice.dev`'s inbox.
3. Treat the relationship as "processing" until a `FollowAccept` or `FollowReject` arrives, or until `Joe` sends an [Unfollow](/entities/unfollow).

### Accepting the Follow Request

`alice.dev` **MUST** answer every `Follow` with a [FollowAccept](/entities/follow-accept) or a [FollowReject](/entities/follow-reject), even if [`manually_approves_followers`](/entities/user#user-manually-approves-followers) is `false`. If `Joe` is already following `Alice` and sends another `Follow`, `alice.dev` **MUST** send a `FollowAccept` again, in case the first was lost.

The answer can wait for `Alice` to decide. There is no time limit on a pending `Follow`.

To accept the follow request, `alice.dev` **MUST** do the following:

1. Create a [FollowAccept](/entities/follow-accept) entity with `Alice` as the author and `Joe` as the follower.
2. Send the `FollowAccept` entity to `social.joe.org`'s inbox.

It then treats `Joe` as a follower of `Alice`.

### Rejecting the Follow Request

To reject the follow request, `alice.dev` **MUST** do the following:

1. Create a [FollowReject](/entities/follow-reject) entity with `Alice` as the author and `Joe` as the follower.
2. Send the `FollowReject` entity to `social.joe.org`'s inbox.

### Cancelling the Follow Request

To cancel a follow request that has not been answered, `social.joe.org` sends an [Unfollow](/entities/unfollow).

### Final Steps

`social.joe.org` **MUST** mark the relationship as "accepted" when it receives a `FollowAccept`, and remove it when it receives a `FollowReject`.

### Delivering Notes

Which entities reach a follower is defined in [Delivery](/federation#delivery).

### Ending the Relationship

`Joe` ends the relationship by sending an [Unfollow](/entities/unfollow). `Alice` ends it by sending a [FollowReject](/entities/follow-reject), which removes `Joe` as a follower. An `Unfollow` is **not** used to remove a follower.

### Flows

Every message here is sent to the inbox of the other user's instance. A follow request is either accepted:

<WireTrace a="social.joe.org" b="alice.dev">
