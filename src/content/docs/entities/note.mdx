A `Note` is a piece of content posted by a [User](/entities/user). Notes can contain text, images, and other media.

<Note>
    Notes are not just limited to microblogging. They can be used for any kind of content, such as forum posts, blog posts, image posts, video posts, audio posts, and even messaging.
</Note>

## Definition

<Entity name="Note" type="Note" checker>
    <div slot="collections">
        - `replies`: [Reference Collection](/structures/collection#reference-collection) of [Note](/entities/note) entities that are replies to this note.
        - `quotes`: [Reference Collection](/structures/collection#reference-collection) of [Note](/entities/note) entities that quote this note.
    </div>

    <Field name="attachments" type="Media[]" required>
        Media attachments to the note. Any media type is allowed. The `content` can [place attachments inside the text](/structures/rich-text#media).
    </Field>
    <Field name="author" type="Reference" required>
        [Reference](/entities#reference) to the `User` considered the author of the note.
    </Field>
    <Field name="category" type="Category">
        Category of the note. Useful for clients to render notes differently depending on their intended purpose.

        <Values values={{
            microblog: "Short posts, like Twitter or Mastodon",
            forum: "Threaded discussions, like Reddit",
            blog: "Long articles, like WordPress or Medium",
            image: "Image posts, like Instagram",
            video: "Video posts, like YouTube or PeerTube",
            audio: "Audio posts, like SoundCloud or Spotify",
            messaging: "Chat messages, like Discord, Element or Signal",
        }} />

        A receiver **MUST** treat an unknown value as if `category` were left out.
    </Field>
    <Field name="content" type="RichText">
        The content of the note.
    </Field>
    <Field name="device" type="Device">
        Device used to post the note. Useful for showing which app posted the note.

        <Field name="name" type="string" required />
        <Field name="version" type="string" />
        <Field name="url" type="string" />
    </Field>
    <Field name="visibility" type={'"public" | "followers" | "mentions"'} required>
        Who can see the note, besides its author:

        - `public`: Anyone.
        - `followers`: The author's followers, the users mentioned in the note, and the authors of the Notes it replies to.
        - `mentions`: Only the users mentioned in the note, and the authors of the Notes it replies to.
    </Field>
    <Field name="is_sensitive" type="boolean" required>
        Whether the note contains "sensitive content". This can be used with `subject` as a "content warning" feature.
    </Field>
    <Field name="mentions" type="Reference[]" required>
        [References](/entities#reference) to [Users](/entities/user) mentioned by the note. The content can also contain mentions, however only the mentions in this field **SHOULD** trigger notifications.
    </Field>
    <Field name="previews" type="LinkPreview[]" required>
        Previews for any links in the publication. This is to avoid the [stampeding mastodon problem](https://github.com/mastodon/mastodon/issues/23662) where a link preview is fetched by every instance that sees the publication, creating an accidental DDOS attack.

        Implementations **SHOULD NOT** trust previews, as a malicious remote instance could fake them to redirect users to malicious links.

        <Field name="link" type="string" required />
        <Field name="title" type="string" required />
        <Field name="description" type="string" />
        <Field name="image" type="string" />
        <Field name="icon" type="string" />
    </Field>
    <Field name="quoting" type="Reference">
        [Reference](/entities#reference) to the note that this note is quoting, if any. Quoting is similar to replying, but does not notify the author of the quoted note.
    </Field>
    <Field name="replies_to" type="Reference">
        [Reference](/entities#reference) to the note that this note is a reply to, if any.
    </Field>
    <Field name="subject" type="string">
        A subject for the note. Useful for clients to display a "content warning" or "spoiler" feature, such as on Mastodon. **MUST** be plain text, not [RichText](/structures/rich-text).
    </Field>
    <Field name="url" type="URI">
        Address of the note's page on its instance, for people to open in a browser. Software that shows the note elsewhere can link to it.
    </Field>
