This page follows one note from `a.example` to `b.example`, from resolving a mention to displaying the note.

<Note>
    The signatures are real. They were made with the [example key](/guides/signing-requests#example-key) from Signing Requests, so you can check them by [exporting its public key](/signatures#exporting-the-public-key).
</Note>

## Sending a Note

The whole exchange looks like this, and the sections below go through each step.

<WireTrace a="a.example" b="b.example" stepper>
    <Message from="a" local>`@alice` posts a note that mentions `@joe@b.example`.</Message>
    <Message from="a" label="GET /.well-known/webfinger?resource=acct:joe@b.example" wire="resolving-the-mention:0">[Resolve the mention](#resolving-the-mention) using WebFinger.</Message>
    <Message from="b" wire="resolving-the-mention:1">Responds with the URL of `joe`'s profile.</Message>
    <Message from="a" label="GET /.versia/v0.7/entities/User/034de9r4fr006" wire="fetching-the-user:0">[Fetch the user](#fetching-the-user) from that URL.</Message>
    <Message from="b" request label="GET /.versia/v0.7/instance" wire="fetching-the-user:1">[Verify the signature](/signatures#verifying-the-signature). `b.example` fetches `a.example`'s metadata if it does not have its public key yet.</Message>
    <Message from="a" request={false}>Responds with its `InstanceMetadata`, which holds the public key.</Message>
    <Message from="b" wire="fetching-the-user:2">Responds with the `User` entity.</Message>
    <Message from="a" local wire="serializing-the-note:0">[Serialize the note](#serializing-the-note).</Message>
    <Message from="a" label="POST /.versia/v0.7/inbox" wire="sending-the-note:0">[Send the note](#sending-the-note) to the inbox.</Message>
    <Message from="b" label="202 Accepted">Verifies the signature with the key it already has, then responds.</Message>
    <Message from="b" local>[Display the note](#displaying-the-note) to `joe`.</Message>
</WireTrace>

`@alice` on `a.example` creates a note with the following content:

```markdown
Hello, @joe@b.example! How are you doing today?
```

`@alice` has mentioned `@joe@b.example` in the note.

### Resolving the Mention

`a.example` resolves the mention by querying `b.example` for the user `joe` using WebFinger.

```bash title="cURL example"
curl "https://b.example/.well-known/webfinger?resource=acct:joe@b.example" -H "Accept: application/jrd+json"
```

`b.example` responds with the following JSON:

```json
{
    "subject": "acct:joe@b.example",
    "links": [
        { // [!code focus:5]
            "rel": "self",
            "type": "application/vnd.versia+json",
            "href": "https://b.example/.versia/v0.7/entities/User/034de9r4fr006"
        }
    ]
}
```

### Fetching the User

`a.example` fetches the user profile of `joe` from `b.example` using the URL provided in the WebFinger response.

```bash
# The request is signed by a.example's instance private key
curl https://b.example/.versia/v0.7/entities/User/034de9r4fr006 \
    -H "Accept: application/vnd.versia+json" \
    -H "User-Agent: CoolServer/1.0 (https://coolserver.example)" \
    -H "Versia-Signature: L8icLiUGIu0kznC4Z1DgSMIzAvounZ0fJ7QsJFl+yFxnkb8qRQ/G2IT549f5yGcpfRFJQF87S12dWUM3161jDQ==" \
    -H "Versia-Signed-By: a.example" \
    -H "Versia-Signed-At: 1733051945"
```

`b.example` [verifies the signature](/signatures#verifying-the-signature) before it answers. That takes `a.example`'s public key, so if `b.example` does not have it yet, it reads it from `a.example`'s [metadata](/entities/instance-metadata):

```bash
curl https://a.example/.versia/v0.7/instance -H "Accept: application/vnd.versia+json"
```

`b.example` then responds with the following JSON. Its response is signed too, and `a.example` verifies it the same way, using `b.example`'s public key.

```json
{
    "id": "034de9r4fr006",
    "type": "User",
    "created_at": "2024-10-13T18:48:19Z",
    "avatar": {
        "url": "https://cdn.example.com/avatars/joe.webp",
        "media_type": "image/webp"
    },
    "display_name": "Joe Swanson (Winter Arc :gigachad:)",
    "username": "joe",
    "manually_approves_subscribers": false,
    "indexable": true,
    "extensions": {
        "pub.versia:custom_emojis": {
            "emojis": [
                {
                    "name": ":gigachad:",
                    "content": {
                        "url": "https://cdn.example.com/emojis/gigachad.png",
                        "media_type": "image/png"
                    }
                }
            ]
        }
    }
}
```

`a.example` now has the user profile of `joe` and can display the note with the correct user information.

### Serializing the Note

Finally, `a.example` serializes the note to send it to `joe`.

```json
{
    "id": "033r20svqa000",
    "type": "pub.versia:social/Note",
    "created_at": "2024-12-01T11:19:04Z",
    "attachments": [],
    "author": "a.example:034d45r3e6003",
    "category": "microblog",
    "content": "<p>Hello, <a href=\"https://b.example/users/034de9r4fr006\" data-mention=\"b.example:034de9r4fr006\">@joe@b.example</a>! How are you doing today?</p>",
    "visibility": "public",
    "is_sensitive": false,
    "mentions": [
        "b.example:034de9r4fr006"
    ],
    "previews": []
}
```

It is now time for `a.example` to send the note to `joe`.

### Sending the Note

`a.example` sends the note to the inbox of `b.example`, which hosts `joe`. `note.json` holds the note above, with no trailing newline.

```bash
# The request is signed by a.example's instance private key
curl -X POST https://b.example/.versia/v0.7/inbox \
    --data-binary @note.json \
    -H "Content-Type: application/vnd.versia+json" \
    -H "User-Agent: CoolServer/1.0 (https://coolserver.example)" \
    -H "Versia-Signature: n+9b5vDR1CcvoxaO+XhWUj6hlVRQeZ+t+EC31SJHD8qHJQ7Y6yd8ZzgrJi9uOWnb7t3ht0EWVa2qF82Jq7ZlCQ==" \
    -H "Versia-Signed-By: a.example" \
    -H "Versia-Signed-At: 1733051946"
```

`b.example` verifies the signature with the key it already has, and responds with a `202 Accepted` status code.

### Displaying the Note

The software on `b.example` processes the note and shows it to `joe` using whatever interface it has.

`joe` can now see the note from `@alice` on `a.example` and respond to it.
