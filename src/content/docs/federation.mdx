This page describes how instances in a Versia network exchange data.

Federation is built on the [HyperText Transfer Protocol (HTTP)](https://datatracker.ietf.org/doc/html/rfc9110) and the [JavaScript Object Notation (JSON)](https://datatracker.ietf.org/doc/html/rfc8259) data format. Instances communicate with each other by sending and receiving JSON payloads over HTTP.

## Inboxes

Every [Instance](/entities/instance-metadata) has one HTTP endpoint called an inbox (`/.versia/v0.7/inbox`), which receives messages for all of its users. Messages are sent to it as JSON payloads over HTTP `POST` requests. See the [Inbox Endpoint](/federation/endpoints#inbox).

Let's consider the following example:

Alice, on the instance `alice.example`, sends a message to Bob on the instance `bob.example`.

To perform this action, Alice's instance sends a `POST` request to Bob's instance's inbox endpoint. This request contains the [Note](/entities/note) entity that Alice wants to send to Bob, with [the appropriate metadata](/federation/http) to ensure the message is valid.

Bob's instance receives the message and processes it according to the rules defined in the [Validation](/validation) document.

## Outboxes

In addition to inboxes, every user has an outbox (at `/.versia/v0.7/entities/User/<id>/collections/outbox`). The outbox is a [Collection](/structures/collection) of the [Notes](/entities/note) that the user has authored.

An outbox **MUST** list only the entities the requesting instance [may fetch](#access). For example, if Alice sends a [Note](/entities/note) whose `visibility` is `mentions` and that only mentions Bob, Alice's instance **MUST** return it in response to a request from Bob's instance, and **MUST NOT** list it in Alice's outbox in response to a request from Joe's instance.

Outboxes are very useful for "backfilling" data when a new instance joins the network. By resolving the outboxes of all new users it encounters, a new instance can quickly catch up on all old messages.

## Delivery

A sender **MUST** deliver each entity to the instances hosting the users below. It **MAY** also deliver it to other instances that [may fetch it](#access), and it may skip instances it refuses to federate with.

| Entity | Delivered to |
| --- | --- |
| [Note](/entities/note), `visibility` is `public` | The author's followers, the users it mentions, and the authors of the Notes it replies to and quotes |
| Note, `visibility` is `followers` | The author's followers, the users it mentions, and the authors of the Notes it replies to |
| Note, `visibility` is `mentions` | The users it mentions and the authors of the Notes it replies to |
| [User](/entities/user), after a change | The user's followers |
| [Follow](/entities/follow), [Unfollow](/entities/unfollow) | The followee |
| [FollowAccept](/entities/follow-accept), [FollowReject](/entities/follow-reject) | The follower |

[Changing an entity](/entities#changing-an-entity) or sending a [Delete](/entities/delete) for it goes to the same audience, as it stands at that moment.

Extensions state the delivery rules for their own entities on their own pages.

## Access

Requests identify an instance, not a user, so access is decided per instance. An instance **MUST NOT** serve an entity to an instance that may not fetch it, and **MUST** answer such a request with a `404 Not Found` status code, so as not to reveal that the entity exists.

| Entity | May be fetched by |
| --- | --- |
| [User](/entities/user) | Any instance |
| [Note](/entities/note), `visibility` is `public` | Any instance |
| Note, `visibility` is `followers` | Instances hosting a follower of the author, a mentioned user, or the author of a Note it replies to |
| Note, `visibility` is `mentions` | Instances hosting a mentioned user or the author of a Note it replies to |

An instance that fetches an entity **MUST** apply the same limits to its own users.

[Collections](/structures/collection) list only the items the requesting instance may fetch. [Transient entities](/entities#transient-entities) cannot be fetched at all. Extensions state the access rules for their own entities on their own pages. An extension **MAY** add to who can fetch an entity, and **MUST** state it on its page. It **MUST NOT** take anyone away.

## Ordering

Delivery order is not guaranteed. An instance can receive a Like before the Note it refers to.

A receiver **SHOULD** fetch referenced entities it does not have. If it cannot, it **MAY** retry later or drop the entity.

An entity with nothing to apply to, such as a [FollowAccept](/entities/follow-accept) with no pending request, **MUST** be ignored, and is not an error.
